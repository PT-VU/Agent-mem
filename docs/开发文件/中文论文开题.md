- # 中文 Proposal

  ## 标题（建议）

  **Agent-mem：面向长程软件与电脑操作任务的“可审计经验记忆”与“渐进可验证护栏”**

  ## 1. 背景与动机

  长程工具使用型任务（如真实仓库修复、真实电脑环境操作）已经成为评估与推动 LLM Agent 能力的核心场景。近年来，多个可执行评测基准的推出推动了该领域的发展：

  ### 1.1 评测基准的演进
  - **SWE-bench** (2024): 首个基于真实GitHub issue/PR的软件工程Agent评测基准，提供可执行的单元测试评估框架[1]。
  - **SWE-bench Verified** (2024-2025): 改进版本，通过人工筛选减少评测误差，提供更可靠的评测harness，显示在可靠设置下Agent能力会发生显著变化[2]。
  - **OSWorld** (2024): 真实可执行电脑环境与多应用任务基准，提供真实GUI操作环境评估[3]。
  - **OSWorld-Human** (2025): 强调效率维度的评测，引入步骤数、延迟、token消耗等过程指标[4]。

  ### 1.2 技术路线的分化
  尽管近年来通过工作流工程（workflow/ACI）、更好的交互接口与执行反馈循环，软件代理表现提升明显（如 SWE-agent 的 ACI 设计[5]），但实际落地仍普遍受限于**长程"过程纪律"崩坏**：错误动作反复、验证不足、对失败缺少体系化复盘，导致级联失败。

  现有改进主要沿两个方向：
  1. **工作流与接口优化**：如SWE-agent强调ACI设计对性能的决定性影响[5]
  2. **记忆与反思机制**：如Reflexion使用语言反思存入episodic memory[6]，Agentless提供简洁的"定位→修复"流程[7]

  ### 1.3 研究趋势与缺口
  评测本身的快速演化提示我们：**要在研究上站得住脚**，不仅要追求pass@k，更应研究"过程层面的可控性与可验证性"。SWE-bench Verified显示在更可靠设置下agent能力会发生显著变化[2]，这强调了过程纪律的重要性。

  同时，2025年的研究趋势显示：
  - **记忆增强架构**：Memory-Augmented Transformers在长上下文任务中表现优异[8]
  - **可验证AI系统**：形式化方法、约束求解、运行时验证成为研究热点[9]
  - **多模态记忆**：GUI操作Agent需要视觉-文本经验的统一表示[10]

  然而，现有方法大多把"经验"保留为文本提示或临时轨迹，缺少一套**可审计（evidence-backed）、可演化（统计晋升/遗忘）、可验证（偏好/约束 + 校验）**的经验资产体系，难以系统性抑制长程任务的级联失败。

  ## 2. 研究缺口

  现有"training-free 改进"主要来自四个方向，但各自存在局限性：

  ### 2.1 工作流与接口工程
  - **代表工作**: SWE-agent强调ACI与工具交互格式对性能的决定性影响[5]
  - **优势**: 显著提升工具使用效率和准确性
  - **局限**: 缺乏对历史经验的系统性利用，每次任务都从零开始

  ### 2.2 简化可解释流水线
  - **代表工作**: Agentless证明了"定位→修复"的简洁流程能取得强基线[7]
  - **优势**: 可解释性强，调试容易
  - **局限**: 经验难以积累和复用，无法从失败中学习

  ### 2.3 反思/文字记忆
  - **代表工作**: Reflexion用语言反思存入episodic memory改善后续试错[6]
  - **优势**: 能够从失败中学习，避免重复错误
  - **局限**: 记忆为文本形式，缺乏结构化，难以进行形式化验证

  ### 2.4 图/检索增强
  - **代表工作**: GraphRAG系列强调图结构检索在多跳关系信息上的优势[11]
  - **优势**: 支持复杂关系推理，检索更精准
  - **局限**: 主要用于知识检索，而非经验记忆和验证

  ### 2.5 最新研究进展中的缺口（2025）
  2025年的研究显示以下趋势但仍存在缺口：

  1. **记忆机制演进**：
     - Memory-Augmented Transformers在长上下文任务中表现优异[8]
     - **但**: 缺乏对经验的可审计性和可验证性支持

  2. **可验证性研究**：
     - 可验证AI系统成为研究热点[9]
     - **但**: 主要关注模型层面的形式化验证，而非执行过程的渐进护栏

  3. **多模态记忆**：
     - GUI操作Agent需要视觉-文本经验的统一表示[10]
     - **但**: 缺乏经验晋升/遗忘的统计机制

  4. **根因分析应用**：
     - RCA技术在Agent错误分析中开始应用[12]
     - **但**: 与经验记忆系统集成不足

  ### 2.6 核心研究缺口总结
  现有方法大多把"经验"保留为文本提示或临时轨迹，缺少一套**可审计（evidence-backed）、可演化（统计晋升/遗忘）、可验证（偏好/约束 + 校验）**的经验资产体系，难以系统性抑制长程任务的级联失败。具体表现在：

  - **可审计性缺口**: 经验建议缺乏可回放的证据支撑
  - **可演化性缺口**: 缺少从候选经验到偏好再到硬约束的渐进晋升机制
  - **可验证性缺口**: 缺乏执行前的fail-fast动作级校验
  - **系统性缺口**: 经验记忆、错误分析、过程验证三者割裂

  ## 3. 核心观点与研究目标

  我们提出 **Agent-mem**：一个面向长程任务的**工作经验记忆（Work-Experience Memory, WEM）插件**。它不依赖模型微调，而是围绕“经验”构建三件事：

  1. **把经验变成可审计资产**：每条建议/规则必须附带可回放证据；
  2. **把经验变成可演化资产**：从“候选经验”到“偏好”再到“硬约束”渐进晋升，并允许降级/遗忘；
  3. **把经验变成可验证资产**：在执行前进行 fail-fast 的动作级校验或偏好排序（PDDL3 preferences/constraints 是一种后端选择）。([University of Strathclyde](https://pureportal.strath.ac.uk/en/publications/preferences-and-soft-constraints-in-pddl3?utm_source=chatgpt.com))

  ### 研究问题（RQs）

  基于上述研究缺口，我们提出以下四个研究问题：

  - **RQ1（价值验证）**：在 SWE-bench Verified[2] / OSWorld[3] 这类可执行评测中，"可审计经验记忆 + 渐进护栏"能否显著降低无效动作与级联失败，并提升最终成功率？这验证了经验记忆系统的整体价值。

  - **RQ2（机制分析）**：经验在**规划阶段**与**执行纠错阶段**的注入，分别贡献多少？它们是否互补？这分析了不同注入时机的相对重要性。

  - **RQ3（可验证性收益）**：将高置信经验固化为"偏好/约束"（借鉴PDDL3理念[13]）相比纯文本提示，是否带来更稳定的收益与更低的方差？这验证了形式化约束的价值。

  - **RQ4（效率提升）**：经验记忆能否改善"完成同一任务所需步数/调用成本"，对应 OSWorld-Human 所强调的效率维度[4]？这评估了系统的实际效用。

  ### 核心假设（可检验）

  - **H1**：Agent-mem 显著降低 invalid_action_rate 与 first_violation_step（首次违例更晚），从而减少 cascade_depth。
  - **H2**：execution-time 的 fail-retry 经验对提升“失败后恢复率”贡献更大；planning-time 的 success-skeleton 对“减少探索噪声/步骤”贡献更大。
  - **H3**：从提示→偏好→约束的渐进化，比直接硬编码约束更稳健（减少过约束误杀）。

  ## 4. 方法概览（只保留研究层次的描述）

  Agent-mem 将历史轨迹抽象成"带证据的经验片段"，借鉴了现代记忆增强架构[8]和可验证AI系统[9]的理念，构建一个三层次的经验记忆系统：

  ### 4.1 经验表示与存储
  - **结构化经验片段**: 每条经验包含{动作序列, 上下文状态, 执行结果, 证据轨迹, 置信度, 使用统计}
  - **证据回放机制**: 每个建议必须附带可回放的执行证据（代码片段、错误日志、修复记录）
  - **多模态支持**: 支持文本、代码、GUI截图等多模态证据存储[10]

  ### 4.2 经验使用时机
  - **规划注入**: 在任务开始时检索相似成功经验，生成"必须做的检查点、推荐顺序、常见坑"，并要求附证据
  - **执行纠错**: 在报错/卡住时检索相似失败与修复经验，给出最短修复建议与验证步骤，结合RCA技术[12]进行根因分析
  - **异步复盘**: 任务完成后进行系统性复盘，更新经验库

  ### 4.3 渐进护栏机制
  - **软偏好（Soft Preferences）**: 影响动作排序，借鉴PDDL3偏好语义[13]
  - **硬约束（Hard Constraints）**: 执行前fail-fast校验，防止明显错误
  - **渐进晋升**: 从文本提示→软偏好→硬约束的三级晋升机制
  - **统计降级**: 基于使用效果和时效性的经验降级与遗忘

  ### 4.4 技术实现路径
  > 我们强调"后端可替换"：PDDL3能提供经典的偏好/约束语义[13]；但为了可实现性，MVP允许先用规则DSL跑通，再在V2.0引入更强的可验证后端。同时考虑与GraphRAG[11]等图检索技术的集成。

  ## 5. 分阶段研究计划与可交付结果

  ### Phase 1：MVP（目标：可复现闭环 + 初版实验）

  - 交付一个可插拔记忆模块：规划注入 + 错误纠错注入
  - 在至少一个基准上跑通（SWE-bench Verified 或 OSWorld）并报告：
    - pass@1 / success rate
    - invalid_action_rate、recovery_success_rate、steps、cost
  - 完成关键消融：无记忆 / 仅规划 / 仅纠错 / 仅提示（soft guidance）

  **预期论文贡献（MVP就能成立）**：证明“经验记忆”不是更多上下文，而是对“过程纪律”的显著改善（用过程指标证明）。

  ### Phase 2：V2.0（目标：论文核心贡献强化 + SOTA 对比）

  - **异步复盘机制**: 引入RCA（根因分析）技术[12]进行系统性错误分析
  - **经验演化系统**: 实现基于统计的晋升/遗忘机制，支持经验生命周期管理
  - **可验证护栏强化**: 增加soft control（偏好排序）并探索hard control（fail-fast），集成PDDL3后端[13]
  - **多模态扩展**: 支持GUI操作的多模态经验记忆[10]
  - **双域评测扩展**: 扩展到SWE + GUI双域评测，并对照最新强基线：
    - SWE-agent（workflow/ACI强基线）[5]
    - Agentless（简单可解释基线）[7]
    - Reflexion（文本记忆范式）[6]
    - Memory-Augmented Transformers（最新记忆架构）[8]
    - GraphRAG增强系统（图检索基线）[11]

  ## 6. 实验设计与评测指标（研究贡献必须落在这里）

  **主评测**：SWE-bench Verified（更可靠）([OpenAI](https://openai.com/index/introducing-swe-bench-verified//?utm_source=chatgpt.com))；OSWorld（真实电脑任务）([科学工具箱](https://www.sciencestack.ai/paper/2404.07972v2?utm_source=chatgpt.com))。
  **核心过程指标**（论文亮点）：

  - invalid_action_rate / violation_rate
  - first_violation_step / cascade_depth
  - recovery_success_rate
  - steps / latency / token / tool calls（对齐 OSWorld-Human 提出的效率痛点）([Emergent Mind](https://www.emergentmind.com/papers/2506.16042?utm_source=chatgpt.com))
    **消融与鲁棒性**：不同阈值的“偏好→约束”晋升策略、不同检索策略（向量 vs 图邻域）、跨环境/仓库迁移。

  ## 7. 预期贡献与影响

  - **方法论贡献**：提出一种“可审计、可演化、可验证”的经验记忆范式，补齐现有文本记忆与workflow工程之间的空白。
  - **评测贡献**：将“级联失败”与“过程违例”引入主评测指标，为 long-horizon agent 提供更科学的改进方向。
  - **实践贡献**：为软件/电脑操作 agent 提供可插拔记忆与护栏模块，降低对模型/提示工程的脆弱依赖。

  ## 8. 风险与对策（审稿人会问）

  - **过约束误杀**：采用渐进晋升（优先soft）、置信阈值与回滚；MVP不主推硬约束。
  - **冷启动**：以通用执行纪律作为prior + 在Verified数据上做稳定评估[2]。
  - **评测偏差**：优先Verified/可执行harness，避免"测试不充分导致的虚假通过"[2]。
  - **经验污染**：实现经验质量评估机制，防止错误经验污染记忆库。
  - **计算开销**：优化检索和验证算法，控制额外计算成本在可接受范围内。
