当前 AgentMem v2.1 能力边界总结
1. 一句话结论

AgentMem v2.1 目前已经是一个有效的“搜索纪律控制器 / 晚期收敛辅助器”，但还不是一个能稳定提升同题 repeat 表现的“成功语义记忆系统”。
它已经能持续积累经验、执行检索、注入提示，并在部分实验里帮助 agent 回到正确 patch family；但这些帮助目前主要体现在 失败路径回避、验证纪律强化、repro path 复用、晚期收敛控制，还没有稳定升级为 bug-specific 代码不变量的提炼、promotion 与早期复用。

2. 当前版本已经明确具备的能力
2.1 真实的经验积累与经验注入

v2.1 不是“开关打开但没工作”。在同题实验里，WithMem 明确产生了长期层对象，包括 failure_cards_v2、repair_patterns_v2、compiler_cards_v21、episode_ledger.jsonl、subtask_instances.jsonl、subtask_edges.jsonl 和 compiler_cards.jsonl，说明 sidecar、compiler、governance 路径都真实运行了。

与此同时，记忆注入也是持续发生的，而不是偶发行为。后期 attempts 的 memory_injected 达到 7 到 8 次，说明系统已经深度介入 planning / retry 流程，而不是只偶尔塞一条提示。

2.2 搜索纪律与验证纪律的强化

当前最稳定、最可重复观察到的收益，不是“记住答案”，而是让 agent 更 disciplined 地解题。
高频被注入的经验主要围绕：

避免重复 unresolved 旧策略

补齐 validation gap

先复现实验路径再 patch

复用已确认的 repro path

在后期触发 closure / stop 发散。

这与更早的 repeat10 结果是一致的：当时系统最有效的帮助也主要体现在 workflow / validation / repro reuse，而不是代码级 invariant 固化。

2.3 一定程度的路径级复用

在较好的那轮 v2.1 单题 repeat10 中，系统把单题正确率从旧版的 2/10 提到了 4/10，并且成功 patch family 被多次找回，而不是只有一次偶然命中。文档明确指出，v2.1 更能把 agent 拉回“复用已确认 repro path + targeted validation”的轨道。

因此，可以说它已经具备一定的 path-level reuse：
它会逐渐复用“怎么靠近答案”的路径组织方式。

3. 当前版本还不具备、或者尚未稳定具备的能力
3.1 还没有稳定的 bug-specific 成功语义记忆

这是当前最重要的能力边界。

无论是旧版 repeat10，还是 v2.1 的两轮单题分析，都反复指出：系统提炼出来的主要是 planning / validation / risk-avoidance 经验，而不是这个 bug 的决定性代码规则。对于 astropy__astropy-14182 这样的题，系统理想上应该学到类似：

data.start_line 需要随 header_rows 动态变化

separator index 必须跟 header_rows 联动

旧的固定 start_line = 3 假设要移除或动态化

但当前注入的主流内容并不是这些“硬规则”，而是“plan better / validate more / avoid broad patches”这类纪律型提示。

3.2 还没有稳定提升“同题 repeat”整体指标

较强的一轮 v2.1 实验显示了正向结果：4/10 resolved，且成功路径被多次复现。
但正式同题对照里，NoMem 是 2/10 resolved，而 WithMem 只有 1/10 resolved + 1/10 incomplete，并且 NoMem 第 1 次就成功，而 WithMem 到第 10 次才成功。文档明确结论是：在这次同题正式验证中，v2.1 没有表现出整体优势，也没有证明能更早找到正确路径。

因此，当前不能稳妥地 claim：

已经稳定提高同题成功率

已经稳定让正确路径更早出现

已经形成稳定的成功复用机制

更准确的表述是：
收益存在，但不稳定；更像后期纠偏，而不是前期加速。

3.3 还不会把成功压成“强策略”

目前 compiler_cards_v21 虽然已经存在，但仍主要停留在 candidate 层；没有看到 resolved 之后，被少数高价值成功卡真正升格成 sticky 的长期策略。文档也明确指出，当前系统会积累大量 failure / repair / compiler 对象，但不会坚定地把“正确修法”升级成强成功卡。

所以它当前更擅长：

记住“不要怎么做”

记住“怎样更稳地验证和收口”

但还不擅长：

记住“这道题真正该怎么做”

4. 当前系统最准确的定位
4.1 它更像 Search Controller，而不是 Stable Bug Memory

早期 repeat10 就已经给出过这个判断：当前 AgentMem 更接近一个 trajectory-shaping assistant / search-shaping layer，而不是一个稳定的 bug-fix memory system。它会帮助 agent 避免一些坏路径，也会在某些轮次帮助它重新找到好路径，但还不能可靠地把 winning path 保留下来。

这个判断在正式同题对照里被进一步强化：
它确实在 attempt_10 成功前施加了计划约束、失败复盘、repro path 复用和 closure 控制，但这些更多表现为“晚期保守纠偏”，不是“前几轮就把正确修法推到台前”。

4.2 它已经开始有长期层，但长期层还处于 candidate 阶段

从 v2.1 施工目标看，当前系统已经完成了这条主线的关键闭环：

成功事实开始采集

run_done 冷路径补 success truth

projected subtask 以 candidate 形式存在

控制层开始消费统一 card

promotion / suppression / budget 开始由治理层接管。

这意味着：
长期层已经不是空壳。
但它目前主要还在“记”和“候选编译”，离“高置信、可推广、可稳定复用的长期知识”还有一段距离。

5. 当前能力边界的最稳表述

如果要把当前版本写成一个严谨的研究结论，我建议这样概括：

已经成立的能力

能持续积累问题相关经验，而不是只做一次性提示。

能把失败经验、验证纪律和 repro path 经验重新注入到后续尝试。

能减少部分明显的坏行为，比如 broad patch、过度探索、ad-hoc script 蔓延。

在部分单题实验中，能提升成功路径复现率，并让 agent 更频繁回到正确 patch family。

尚未成立的能力

还不能稳定提升同题 repeat 的整体正确率。

还不能稳定让正确路径更早出现。

还没有把 resolved patch family 压成 bug-specific 的强成功卡。

还没有形成稳定的 semantic-level reuse，只形成了 path-level reuse。

6. 为什么会这样：当前系统的核心瓶颈
6.1 纪律卡太多，成功卡太弱

当前真正被注入的内容，主要是风险规避、验证纪律、planning/checklist 和 retry guidance。文档明确指出，当前“经验内容”主要是：

失败后如何收敛

计划里如何补验证

什么时候该停止继续发散

而不是 bug invariant 本身。

6.2 Gate 在评估，但还没有真正过滤

同题正式验证里，gate 并非不存在，而是：

external_ratio 多数通过

buffer_ratio / action_error_coverage 多数不通过

passed 多数为 false

但 hard_fail_enabled = false

因此，低质量对象仍继续保留为 candidate 并参与后续编译/注入。文档明确指出，这正是“记忆系统越来越活跃，但收益没有同步闭合”的原因之一。

6.3 Success promotion 还不够强

在较强的那轮实验里，文档已经明确把下一步重点收敛到三件事：

把 resolved patch family 编译成 bug-specific compiler card

修热路径 success fact 覆盖

让 official eval 真正推动 successful card promotion。

这说明当前最大缺口不在于“没有长期层”，而在于长期层里真正 sticky 的成功知识还没有升格出来。

7. 当前版本最稳的研究定位

如果现在要对外或对内做一版最稳的定位，我建议这样写：

AgentMem v2.1 当前已经实现了真实的经验积累、经验注入和后期收敛辅助；它对 agent 的主要帮助体现在搜索纪律、验证纪律和失败路径回避。它在部分单题实验中可以提升成功路径复现率，但在正式同题对照中，还没有稳定转化为整体正确率优势。当前系统的主要缺口是：未能把 resolved patch family 压成高置信、可 promotion 的 bug-specific 成功卡。

8. 下一步最关键的方向

基于现有实验，我认为最值得继续推进的，不是再加新对象，而是三件事：

把成功 patch family 压成更短、更硬的成功卡
也就是文档里提到的 BugInvariantCard / SuccessPathCard 方向。

让 official eval 真正推动成功卡 promotion，而不是一直停留在 candidate。

让 gate 真正承担过滤职责，减少低质量 candidate 继续污染 compiler 和注入层。

最后一段总结

当前 AgentMem v2.1 的能力边界已经比较清楚：它会复盘失败、会约束发散、会推动验证收敛，也开始具备一定的路径级复用；但它还不会稳定把“为什么这个 patch 会成功”压成高置信、可 promotion、可提前复用的成功语义。
因此，它现在最适合被理解为一个有效的晚期收敛辅助器 / 搜索纪律控制器，而不是一个已经成熟的成功语义记忆系统。
