  1.2 根本问题定位

  Agentmem效果不显著的根本原因在于系统性实现滞后于先进架构设计：

  1.
  经验质量不足：提取停留在"发生了什么"的记录层，未达到"为什么发生"的理解层
  2. 检索精度不够：简单规则匹配难以找到真正相关经验
  3. 注入时机被动：只在明显事件触发，错过最佳干预时机
  4. 缺乏环境适配：通用建议对特定环境效果有限
  5. 关键模块缺失：剪枝与提炼、深度RCA等核心模块未实现

该草案方向正确，问题定位大体准确（经验质量、检索效率、被动触发、工程化不足），但存在一个关键实现断点未被显式列为最高优先级：当前 with_mem 的检索结果没有形成对模型输入的有效闭环注入，因此很难在步数和成功率上体现显著增益。

9.2 与实验数据的一致性检查（02_first50_unlimited）

根据指标文件：
1. `.../no_mem/metrics/metrics_experiment01_first50_nomem_unlimited.json`
2. `.../with_mem/metrics/metrics_experiment02_first50_withmem_unlimited.json`

关键事实：
1. 成功率：两组均为 `50/50 = 100%`
2. 平均步数：with_mem `103.96` vs no_mem `104.3`（差异极小）
3. 总成本：with_mem `5.792353` vs no_mem `6.094378`（约 5% 降低）
4. 工具调用成功率：with_mem `0.993779` vs no_mem `0.995544`（with_mem 略差）
5. 失败动作：with_mem `32` vs no_mem `23`

结论：草案对“收益有限且伴随副作用”的判断与实验数据一致。

9.3 关键架构事实（影响草案落地优先级）

1. 记忆闭环未打通（最高优先级问题）：
`bridge_hook.py` 中外部工具结果仅通过日志输出（`[tool_a stdout]`/`[tool_b stdout]`）记录，未注入到下一轮模型 query 的消息中。
这会导致“有检索、无决策影响”。

2. 在线检索主路径未充分使用 embedding：
`memory_agent.py` 的 `retrieve_for_planning/retrieve_for_repair` 主要走规则与子图评分，真正 embedding 相似检索主要在 `search_experience` 路径，在线闭环利用不足。

3. 多处 MVP/占位实现仍在关键路径：
`kg_writer.py` 中 `emb_tool_output`、`emb_diff_summary` 仍为占位处理；
`retriever.py`、`rca_agent.py`、`local_storage.py` 中仍有大量简化分支/未实现点。

4. 事件触发仍偏被动：
当前核心 Hook 主要覆盖 `plan_generated`、`action_error`、`run_done`；缺少对成功动作与 step 级过程的持续学习闭环（如 `on_action_executed`/`on_step_done` 利用不足）。

5. 实验可复现性仍需加强：
部分历史产物仍带旧路径与重跑痕迹（如 output_dir 指向旧目录、`run_batch_exit_statuses.yaml` 仅反映最后 slice），建议在阶段3先统一实验元数据规范。

9.4 对草案的修订建议（不改原文，仅给执行层建议）

1. 将“闭环注入”提升为阶段1第1优先级，不应晚于存储栈升级。
2. 将“Neo4j/FAISS/Parquet”从硬前置改为“闭环打通后按瓶颈触发”的第二梯队任务。
3. 将阶段目标从“整体成功率提升”调整为“困难样本集提升 + token/step/错误类型结构优化”。
4. 建立强约束验收：每一项升级必须在 paired with_mem/no_mem 对照中体现统计显著的方向性收益，至少在一个核心指标上稳定改善。

9.5 最终评估结论

该草案可作为阶段3战略框架，但执行层必须先解决“记忆建议无法进入模型决策”的基础问题；否则即使完成检索和存储升级，收益也大概率继续停留在边际改善。

十、补充升级方向（吸收对比分析建议）

10.1 经验抽象层（从实例经验到可复用模式）

问题：当前经验提取偏实例化，跨任务迁移能力有限。

补充方案：
1. 新增抽象经验对象（建议名：`AbstractExperience`）：
`pattern_type`、`abstracted_intent`、`success_conditions`、`failure_avoidance`。
2. 抽象层不替代原始轨迹，而是作为“二级知识层”与 evidence refs 绑定。
3. 检索优先返回“抽象模式 + 最近实例证据”，降低建议碎片化。

验收指标：
1. 抽象经验复用率（跨任务被命中的比例）持续上升。
2. 相同错误类型下建议重复率下降。

10.2 主动式经验注入（触发器细化）

问题：现有注入触发点偏被动，可能错过最优干预时机。

补充方案：
1. 在保持现有 `plan_generated/action_error` 的同时，新增触发器策略：
`first_file_access`、`consecutive_failures`、`before_test_run`、`after_success`。
2. 每次注入受 token 预算和置信度阈值约束，避免提示污染。
3. 所有主动注入必须可审计（记录触发原因、注入内容、后续结果）。

验收指标：
1. 主动注入触发后，局部窗口（后续 N 步）错误密度下降。
2. 无明显 token 膨胀或成本失控。

10.3 对比学习闭环（with_mem vs no_mem 同题分歧分析）

问题：现有 A/B 结论未沉淀为可学习资产。

补充方案：
1. 引入 `ComparativeAnalyzer`，按同一 instance 对齐两条轨迹。
2. 输出三类结构化结论：
`少走弯路点`、`with_mem 独有失效点`、`关键记忆干预点`。
3. 将“有效干预模式”回写到抽象经验库，形成反哺闭环。

验收指标：
1. 分歧点解释率（with_mem 变化可被干预点解释的比例）可量化。
2. 形成可复用的干预模式清单并进入在线检索。

10.4 元认知经验（最小可行范围）

问题：当前经验主要回答“做什么”，缺少“如何思考/验证”。

补充方案（MVP）：
1. 仅实现三类元认知规则：
问题分解、失败后修复策略、提交前自检清单。
2. 元认知规则以低频高置信方式注入，避免冗长推理污染。
3. 与任务经验分开存储，独立评估采纳率。

验收指标：
1. 元认知建议采纳率可统计。
2. 在不降成功率前提下，`exit_cost` 和重复失败链条占比下降。
