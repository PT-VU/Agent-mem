## 1. 目标与验收口径

目标：将两篇论文中“失败归因、经验抽取、纠错反馈”的可落地部分，融合进当前 AgentMem 的 RCA 与经验提炼链路，直接服务 SWE-bench 任务成功率提升与成本下降。

验收口径（阶段性）：
1. RCA 输出从“粗粒度错误类型”升级为“步骤级决定性错误 + 传播链 + 模块归因 + 可执行纠正建议”。
2. 经验抽取从“通用建议”升级为“结构化 failure/repair/preventive pattern”，可被检索和注入。
3. with_mem 运行产物中可追溯“哪条经验在第几步注入并产生何种影响”。

## 2. 两篇论文可迁移能力抽取

## 2.1 `when+where.pdf`（Which Agent Causes Task Failures and When?）
可迁移重点：
1. 失败归因对象必须同时包含 `who + when`（责任体 + 决定性步骤）。
2. 对多错误轨迹采用“最早决定性错误优先”原则（earliest decisive step）。
3. 步骤级归因显著更难，必须单独建模与评测，不能用任务级成功率替代。

落地启示：
1. 我们的 RCA 不能只在末端失败点提取“error_type”，必须回溯步骤并排序候选关键步。
2. 需要显式记录 step-level 证据字段（`step_index/source_event/action_text`），否则无法做 when 归因。
3. 需要建立 RCA 专用评测集和指标（step attribution precision/coverage）。

## 2.2 `归因.pdf`（Where LLM Agents Fail and How They Can Learn from Failures）
可迁移重点：
1. 模块化错误分类（memory/reflection/planning/action/system）。
2. 级联失败建模（早期根因传播到后续动作）。
3. AgentDebug 式循环：定位关键错误 -> 生成针对性反馈 -> 重试并验证。

落地启示：
1. RCA 输出必须带 `error_module` 和 `propagation_chain`，与当前架构预期一致。
2. 经验抽取应围绕“根因-修复-验证”三元闭环，而非只抽“修复建议文本”。
3. 注入策略应从被动检索扩展到关键节点主动注入（before_test_run / consecutive_failures 等）。

## 3. 与现有架构预期对齐（Agent-mem架构.md）

现有架构已定义但需工程化补齐的关键点：
1. RCA 输出：`root_cause_nodes`、`propagation_chain`、`error_module`、`corrective_actions`、`preventive_checks`。
2. 事实图与信念图分离：RCA 写入信念层，不改写事实层。
3. 基于 RCA 的剪枝提炼：保留关键转折与失败修复最短链，降权冗余尝试。
4. 评测需覆盖 cascade reduction、retrieval hit quality、constraint/validator 价值。

---

## 4. 当前实现差距（代码视角）

基于当前 `agent_mem` 实现，主要差距如下：
1. `processing/rca_agent.py` 仍是规则化 MVP，缺少“决定性步骤”评分机制。
2. 失败归因以 `outcome=fail` 节点为主，缺少跨步骤候选集合与 earliest tie-break。
3. 模块化错误分类没有形成统一规则库与可测试标签映射。
4. RCA 结果尚未形成稳定的“经验对象”产线（failure card/repair pattern/preventive rule）。
5. 注入与归因之间缺乏统一的 `intervention_id` 追踪字段，难以验证“记忆是否起效”。

## 5. 融合方案（RCA + 经验抽取 V2）

## 5.1 数据契约升级（RCA可观测基础）
先决条件：ProblemFile V2 在主链启用（与阶段4文档保持一致）。

新增/强制字段：
1. 追踪：`instance_id`、`run_id`、`step_index`、`source_event`、`action_text`、`action_family`。
2. 失败语义：`failure_signature.error_stage`、`exit_code`、`is_timeout`、`nonzero_exit`。
3. 执行摘要：`execution_stats`、`test_stats`、`patch_stats`。
4. 注入追踪：`intervention_id`、`intervention_source`（planning/execution/proactive）。

## 5.2 RCA V2 流水线（异步）
对每个未解决任务执行以下流程：
1. 构建时序轨迹：按 `step_index` 排序，形成 action timeline。
2. 识别失败终点：`run_done=unresolved` 或关键测试失败终点。
3. 候选关键步生成：从终点向前回溯，筛出错误步、重试起点、关键分叉点。
4. 决定性评分：对每个候选步计算 `decisive_score`。
5. 最小根因集合提取：按分数与覆盖关系抽取 `root_cause_nodes`（最小集）。
6. 传播链重建：生成 `propagation_chain`（根因到终点）。
7. 反馈生成：产出 `corrective_actions` + `preventive_checks` + `confidence` + `evidence_refs`。

建议的初版评分（规则+统计混合）：
`score = w1*temporal_earliness + w2*causal_link + w3*error_severity + w4*retry_dependency + w5*evidence_consistency`

说明：
1. 同分时按最早步骤优先（论文原则）。
2. 首版可规则化实现，后续再引入轻量 learned ranker。

## 5.3 模块化错误分类器（taxonomy）
对齐 `memory/reflection/planning/action/system` 五类，并维护可测试映射表：
1. memory：错误引用历史经验、过期经验误导、检索错配。
2. reflection：错误复盘结论、错误自我修正方向。
3. planning：计划漏步骤、验证缺失、顺序错误。
4. action：命令参数错、文件路径错、补丁定位错。
5. system：环境缺依赖、权限/超时、容器异常。

交付要求：
1. 每个类别至少 3 条触发规则 + 1 个置信度估计来源。
2. 分类结果写入 RCA 输出和 failure card。

## 5.4 经验对象化（用于检索和注入）
新增三类经验产物：
1. `failure_card_v2`
   - 字段：`error_module/error_type/root_cause_nodes/propagation_chain/evidence_refs/candidate_fixes`。
2. `repair_pattern_v2`
   - 字段：`trigger_signature -> fix_action_template -> expected_verification`。
3. `preventive_rule_v2`
   - 字段：`when(context) -> should_check(action)`，并带统计支持度。

经验提炼原则：
1. 保留最短“失败 -> 修复 -> 验证”链。
2. 删除根因后无信息增益的重复步骤。
3. 将具体实例参数抽象为模板槽位（路径、测试命令、模块名）。

## 5.5 注入策略升级（主动+被动）
1. planning-time：注入 `preventive_rule_v2` 与相似成功骨架。
2. execution-time：根据 `failure_card_v2` 注入 `next_step_fix + expected_outcome`。
3. proactive 触发：`first_file_access`、`consecutive_failures`、`before_test_run`、`after_success`。
4. 每次注入必须落 `intervention_id`，用于后续因果评估。

## 5.6 对比学习回路（with_mem vs no_mem）
新增差异分析器，按 instance 对齐两条轨迹，提取：
1. `detour_reduction`（with_mem 少走的弯路）。
2. `mem_unique_failures`（仅 with_mem 出现的新失败模式）。
3. `effective_interventions`（明确帮助成功的注入点）。

## 6. 工程实施计划（四个里程碑）

## M1（P0）：数据与可观测性打底（3-4天）
任务：
1. ProblemFile V2 字段接入主链（含注入追踪字段）。
2. 事件日志完整性校验（无日志即失败）。
3. RCA 输入快照生成器（统一轨迹读入结构）。

涉及文件：
1. `agent_mem/core/problem_file.py`
2. `agent_mem/processing/action_logger.py`
3. `agent_mem/integration/sweagent_adapter.py`

验收：
1. 5 个样本实例都能生成可用于 RCA 的完整轨迹快照。
2. 每条注入记录具备 `intervention_id`。

## M2（P0）：RCA V2 核心实现（5-7天）
任务：
1. `rca_agent.py` 实现候选关键步生成 + 决定性评分 + 最小根因集合。
2. 实现传播链构建与模块归因分类器。
3. 输出 schema 固化（JSON 可被测试断言）。

涉及文件：
1. `agent_mem/processing/rca_agent.py`
2. `agent_mem/processing/error_handler.py`
3. `agent_mem/core/belief_graph.py`

验收：
1. 每个 unresolved 任务都产出 RCA 结构化结果。
2. 结果包含 `root_cause_nodes + propagation_chain + error_module + evidence_refs`。

## M3（P1）：经验对象化与注入闭环（4-6天）
任务：
1. 生成 `failure_card_v2 / repair_pattern_v2 / preventive_rule_v2`。
2. 检索层支持按 `error_module/error_stage/action_family` 过滤。
3. 注入层支持 proactive 触发与注入追踪。

涉及文件：
1. `agent_mem/processing/failure_card.py`（新建）
2. `agent_mem/retrieval/memory_agent.py`
3. `agent_mem/integration/sweagent_adapter.py`
4. `agent_mem/processing/abstract_experience.py`

验收：
1. with_mem 运行中至少 90% 的注入可回溯到具体经验对象与证据。
2. 至少一种 proactive 触发在 first50 中可稳定触发并有记录。

## M4（P1）：评测与回归（3-5天）
任务：
1. 增加 RCA 单测/集成测/样本回放测试。
2. 新增对比分析报表（with_mem vs no_mem 的干预有效性）。
3. 完成 first50 对照复跑并生成阶段报告。

涉及文件：
1. `agent_mem/tests/test_rca_agent.py`（新建）
2. `agent_mem/tests/test_failure_card.py`（新建）
3. `PDDL_work_mem/06_artificial_intelligence/experiments/common/collect_run_metrics.py`
4. `PDDL_work_mem/06_artificial_intelligence/experiments/common/compare_trajectories.py`

验收：
1. RCA 相关测试全绿。
2. 形成 with_mem/no_mem 的可复现实验报告（含 step 级归因字段统计）。

## 7. 测试与评估指标（RCA专项）

功能正确性：
1. `rca_output_schema_valid_rate = 100%`
2. `unresolved_with_failure_card_rate >= 95%`
3. `intervention_traceability_rate >= 90%`

归因质量：
1. `step_attribution_coverage`（有决定性步骤的失败占比）
2. `earliest_decisive_consistency`（是否满足最早决定性步骤原则）
3. `module_classification_agreement`（人工抽样一致率）

业务收益（以 first50 为主）：
1. solved rate 相对 no_mem 稳定正增益。
2. `tool_failed_actions` 持续下降。
3. `total_cost` 或 `mean_steps` 至少一项下降。
4. `cascade_failure_span`（传播链长度）下降。

## 8. 风险、缓解与回滚

风险1：归因噪声高，建议误导执行。  
缓解：对低置信 RCA 仅做软提示，不直接强注入。  
回滚：关闭 proactive 注入，仅保留被动 repair 检索。

风险2：字段扩展导致历史数据读取失败。  
缓解：严格 `from_dict` 向后兼容 + 回放测试。  
回滚：保留 V1 读取分支并在写路径降级。

风险3：RCA 计算开销过高影响实验吞吐。  
缓解：异步队列执行 + 采样策略 + 缓存。  
回滚：仅对 unresolved 样本执行完整 RCA。
