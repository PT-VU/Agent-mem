# 阶段7：AgentMem v2.1 接口与状态转移规范 1.0

**日期**：2026-03-14  
**状态**：Draft / Normative  
**上游文档**：`v2.1 实施约束清单1.0.md`  
**文档定位**：把 v2.1 的实施约束继续下沉到接口级和状态机级，直接指导实现、测试和后续 code review。

> 一句话结论：**v2.1 的实现边界，最终要靠事件协议、函数契约、状态转移和降级语义来锁住。**

---

## 0. 本文档解决什么问题

`v2.1 实施约束清单1.0.md` 已经定义了：

1. 哪些能力必须做
2. 哪些能力必须后置
3. 哪些对象可以进入主链
4. 哪些对象不能提前进入主链

但真正开始编码时，还会马上遇到四类问题：

1. 事件载荷到底长什么样
2. 每个核心函数的输入/输出/错误语义是什么
3. 各对象状态怎么转，谁有权转
4. 失败时如何降级，怎样做到不破坏在线控制

本文档专门回答这四件事。

---

## 1. 规范级原则

本文档里的关键词采用下面语义：

- **必须**：v2.1 默认实现必须满足
- **应该**：推荐默认实现满足，除非有明确工程理由
- **可以**：允许作为增强项存在，但不构成默认能力
- **禁止**：v2.1 默认实现中不允许出现

## 2. 模块接口总览

v2.1 默认涉及的核心模块如下：

| 层级 | 模块 | 角色 | 输入 | 输出 |
| --- | --- | --- | --- | --- |
| Hook | `ExternalToolBridgeHook` | 事件监听、提示注入、轻量记录 | SWE-agent 生命周期事件 | `SWE_AGENT_EXT_EVENT_JSON`、注入 hints |
| Router | `dispatcher.py` / `agent_mem_main.py` | 事件路由与主入口 | `SWE_AGENT_EXT_EVENT_JSON` | Adapter 响应 JSON |
| Orchestrator | `SWEAgentAdapter` | 统一编排 | 事件 dict | 写入 GraphStore / sidecar / 返回工具响应 |
| Fact | `ActionLogger` | 动作级事实落库 | action payload | `ProblemFile` |
| Learning | `ExtractionOrchestrator` | `run_done` 冷路径抽取 | task actions + context | `attempt_summary_v1` 等 |
| Feedback | `EvaluationFeedbackProcessor` | official eval 写回 | eval payload | promote/suppress report |
| Retrieval | `MemoryAgent` | 检索、去重、排序、生成建议 | query context | `recommendations` / `retrieval_debug` |
| Sidecar | `EpisodeLedgerStore` | append-only 事实账本 | normalized event | JSONL 记录 |
| Projection | `SubtaskProjector` / `SubtaskEdgeBuilder` | 冷路径投影 | attempt evidence | `SubtaskInstance` / `SubtaskEdge` |
| Compiler | `CardCompiler` | 统一卡片编译 | summary/card/pattern/subtask | `CompilerCard[]` |
| Governance | `ObjectGovernancePolicy` | 去重、状态机、配额 | candidate objects | governed objects |

## 3. 统一事件协议

v2.1 的跨进程协议仍基于环境变量 `SWE_AGENT_EXT_EVENT_JSON`。

## 3.1 顶层字段

所有事件必须包含以下顶层字段：

| 字段 | 类型 | 是否必须 | 说明 |
| --- | --- | --- | --- |
| `version` | `str` | 应该 | 默认 `v1` |
| `event` | `str` | 必须 | 事件类型 |
| `agent` | `str` | 应该 | 发起 agent 名称 |
| `instance_id` | `str` | 必须 | SWE-bench 实例标识 |
| `run_id` | `str` | 应该 | 批次或运行标识 |
| `attempt_id` | `str` | 应该 | 同一 instance 下的 attempt 标识 |
| `trace_id` | `str` | 应该 | 当前事件链追踪标识 |
| `step_index` | `int` | 应该 | 当前 step 序号 |
| `timestamp` | `str` | 应该 | ISO 时间戳 |

## 3.2 事件类型白名单

v2.1 默认只支持：

1. `plan_generated`
2. `action_error`
3. `run_done`
4. `official_eval_feedback`

### 禁止事项

1. 不得在 v2.1 默认主线上新增 `subtask_start`
2. 不得在 v2.1 默认主线上新增 `subtask_end`
3. 不得要求所有调用方立即迁移到新的事件协议版本

## 4. 事件级接口契约

## 4.1 `plan_generated`

### 触发位置

- `ExternalToolBridgeHook.on_actions_generated()`
- 经 `agent_mem_main.handle_event()` 路由到 `SWEAgentAdapter.handle_plan_generated()`

### 输入字段

| 字段 | 类型 | 是否必须 | 说明 |
| --- | --- | --- | --- |
| `thought` | `str` | 应该 | 当前思考文本 |
| `action` | `str` | 必须 | 当前准备执行的动作 |
| `runtime_guard` | `dict` | 可以 | 当前运行时控制信号 |

### 输出字段

`handle_plan_generated()` 必须返回：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `version` | `str` | 协议版本 |
| `event_handled` | `str` | 固定为 `plan_generated` |
| `task_id` | `str` | 当前任务标识 |
| `action_id` | `str` | 规划动作对应的事实对象 ID |
| `trace_id` | `str` | 响应链 trace_id |
| `planning_tips` | `list` | 供注入的建议 |
| `evidence_refs` | `list` | 关联证据 |
| `confidence` | `float` | 检索置信度 |
| `retrieval_debug` | `dict` | 调试字段 |
| `timestamp` | `str` | 响应时间 |

### 错误语义

1. 检索失败时不得阻塞主代理；
2. 允许返回空 `planning_tips`；
3. 必须保留最小 `task_id / action_id / timestamp`。

### 幂等要求

同一 `(instance_id, attempt_id, step_index, trace_id, event=plan_generated)` 的重复事件，应该被视作可重复处理事件，允许重放但不得导致无界膨胀。

## 4.2 `action_error`

### 触发位置

- `ExternalToolBridgeHook.on_action_error()`
- 经 `agent_mem_main.handle_event()` 路由到 `SWEAgentAdapter.handle_action_error()`

### 输入字段

| 字段 | 类型 | 是否必须 | 说明 |
| --- | --- | --- | --- |
| `error_type` | `str` | 应该 | 错误分类 |
| `error_message` | `str` | 应该 | 错误信息 |
| `thought` | `str` | 可以 | 动作前思考 |
| `action` | `str` | 必须 | 失败动作 |

### 输出字段

必须返回：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `version` | `str` | 协议版本 |
| `event_handled` | `str` | 固定为 `action_error` |
| `task_id` | `str` | 当前任务标识 |
| `action_id` | `str` | 失败动作事实 ID |
| `repair_tips` 或等价 recommendations | `list` | 修复建议 |
| `evidence_refs` | `list` | 关联证据 |
| `confidence` | `float` | 置信度 |
| `retrieval_debug` | `dict` | 调试字段 |
| `timestamp` | `str` | 响应时间 |

### 错误语义

1. 错误恢复检索失败时不得阻塞主代理；
2. 应允许空建议返回；
3. 必须保留错误动作的事实记录。

## 4.3 `run_done`

### 触发位置

- `ExternalToolBridgeHook.on_run_done()`
- 经 `agent_mem_main.handle_event()` 路由到 `SWEAgentAdapter.handle_run_done()`

### 输入字段

| 字段 | 类型 | 是否必须 | 说明 |
| --- | --- | --- | --- |
| `trajectory_steps` | `int` | 应该 | 本次轨迹步数 |
| `exit_status` | `str` | 必须 | 退出状态 |
| `has_submission` | `bool` | 应该 | 是否提交 patch |

### v2.1 扩展字段

`run_done` 在 v2.1 中应该逐步支持补全：

1. `touched_files`
2. `diff_summary`
3. `validation_summary`
4. `patch_digest`
5. `worktree_digest`

### 输出字段

`handle_run_done()` 必须至少返回：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `version` | `str` | 协议版本 |
| `event_handled` | `str` | 固定为 `run_done` |
| `task_id` | `str` | 当前任务标识 |
| `task_summary` | `dict` 或 `str` | 收尾摘要 |
| `belief_update` | `dict` | belief 写回信息 |
| `attempt_summary_info` | `dict` | `attempt_summary_v1` 写入信息 |
| `failure_card_info` | `dict` | failure card 生成或跳过信息 |
| `extraction_pipeline` | `dict` | 抽取流水线结果 |
| `timestamp` | `str` | 响应时间 |

### v2.1 新增输出建议

应该补充：

1. `sidecar_write_report`
2. `success_fact_report`
3. `projection_report`
4. `compiler_report`
5. `governance_report`

### 错误语义

1. `run_done` 是冷路径，可失败但不得影响已经完成的代理运行；
2. 即使抽取失败，也必须尽量落下：
   - 最小 `attempt_summary_v1`
   - 最小 `sidecar` 事实记录
3. 失败时必须返回 `skipped_reason` 或 `error_stage`。

## 4.4 `official_eval_feedback`

### 触发位置

- 评测阶段外部触发
- 经 `agent_mem_main.handle_event()` 路由到 `SWEAgentAdapter.apply_evaluation_feedback()`

### 输入字段

| 字段 | 类型 | 是否必须 | 说明 |
| --- | --- | --- | --- |
| `instance_id` | `str` | 必须 | 实例标识 |
| `official_eval_status` 或 `outcome` | `str` | 必须 | 评测结论 |
| `eval_ref` 或 `report_path` | `str` | 可以 | 评测报告引用 |
| `patch_text` 或 `patch_path` | `str` | 可以 | patch 内容或路径 |
| `changed_files` | `list[str]` | 可以 | 修改文件列表 |
| `validation_summary` | `dict` | 可以 | 验证摘要 |
| `task_summary` | `str` | 可以 | 任务摘要 |
| `run_id` | `str` | 应该 | 运行标识 |
| `attempt_id` | `str` | 应该 | attempt 标识 |
| `trace_id` | `str` | 可以 | 跟踪标识 |

### 输出字段

必须至少返回：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `version` | `str` | 协议版本 |
| `event_handled` | `str` | 固定为 `official_eval_feedback` |
| `instance_id` | `str` | 实例标识 |
| `feedback_report` | `dict` | promote / suppress 结果 |
| `timestamp` | `str` | 响应时间 |

### v2.1 写回边界

`official_eval_feedback` 只允许直接推动：

1. `attempt_summary_v1.final_outcome`
2. governance 对象状态
3. `CompilerCard.promotion_state`
4. `SubtaskInstance.eval_context`
5. `SubtaskEdge.eval_support`

### 禁止事项

1. 不得直接覆写 `SubtaskInstance.local_result_status`
2. 不得直接把 `SubtaskEdge` 写成最终因果真理
3. 不得把全部参与对象一把 promote

## 5. 函数级契约

## 5.1 `ExternalToolBridgeHook._build_event_payload(event_name, **extra)`

### 责任

统一构造跨进程事件 payload。

### 必须保证

1. 自动补齐通用字段；
2. 同类事件字段稳定；
3. 不依赖下游模块存在额外隐式字段。

### v2.1 要求

在不破坏现有调用方的前提下，允许增量补充事实层字段，但不得删除现有稳定字段。

---

## 5.2 `ExternalToolBridgeHook.on_model_query(messages, agent)`

### 责任

把已选中的 hints 统一注入到模型查询消息流。

### 输入

- `messages: list[dict[str, str]]`
- `agent: str`

### 输出

无显式返回；通过原地修改 `messages` 完成注入。

### 必须遵守

1. 只消费经过 `MemoryAgent + CardCompiler + Governance` 的卡片化提示；
2. 必须受 `max_hints`、`hint_char_budget`、family cooldown 控制；
3. 注入失败时不得影响主代理继续推理。

---

## 5.3 `ExternalToolBridgeHook.on_action_executed(step)`

### 当前角色

当前实现主要做：

1. success-like 观测识别
2. consecutive failure reset
3. intervention 推进

### v2.1 目标角色

新增：

1. 最小成功事实归一化
2. append-only sidecar 写入
3. 可选转发到 `handle_action_success()`

### 必须遵守

1. 不得在此处做重型语义抽取；
2. 不得在此处生成完整 `SubtaskInstance`；
3. sidecar 写入失败必须静默降级为 telemetry。

---

## 5.4 `SWEAgentAdapter.handle_action_success(...)`

### 责任

把单步成功动作写为 `ProblemFile`，作为事实层原子。

### 当前输入

- `action`
- `thought`
- `agent_name`
- `output`

### v2.1 推荐扩展输入

应该逐步支持：

1. `instance_id`
2. `run_id`
3. `attempt_id`
4. `trace_id`
5. `step_index`
6. `touched_files`
7. `diff_content`
8. `test_output`

### 输出

必须至少返回：

1. `event_handled = action_success`
2. `task_id`
3. `action_id`
4. `timestamp`

### 幂等建议

应该支持基于 `(instance_id, attempt_id, step_index, action fingerprint)` 的轻量去重。

---

## 5.5 `ActionLogger.log_action(...)`

### 责任

将动作归一化为 `ProblemFile` 并写入事实层。

### 输入核心字段

1. `action_type`
2. `intent_text`
3. `inputs`
4. `tool_calls`
5. `outcome`

### 可选证据字段

1. `stdout`
2. `stderr`
3. `diff_content`
4. `test_output`
5. `touched_files`
6. `env_info`
7. `metadata`

### 输出

- `ProblemFile`

### 必须遵守

1. 没有 `current_task_id` 时必须报错或由上游先补 task 上下文；
2. `ProblemFile` 是事实原子，不在这里做长期对象治理；
3. 证据引用应优先保存为 ref，而不是复制大块内容进入主对象。

---

## 5.6 `SWEAgentAdapter.handle_run_done(event_data)`

### 责任

这是 v2.1 冷路径的总编排入口。

### 必须负责的步骤

1. 关闭或补齐 task context
2. 计算 `task_closed_cleanly`
3. 汇总 `run_done_context`
4. 保底生成 `attempt_summary_v1`
5. 触发 `ExtractionOrchestrator.process_attempt()`
6. 补齐成功事实
7. 写 sidecar
8. 触发 `SubtaskProjector / SubtaskEdgeBuilder`
9. 驱动 `CardCompiler / Governance`

### 必须保证

1. 抽取失败不影响 task 收尾；
2. 至少有一个最小 `attempt_summary_v1` 落库；
3. 所有可跳过步骤必须记录 `skipped_reason`。

---

## 7. 核心状态机

## 7.1 Attempt 状态机

```text
created
  -> active
  -> run_done_unresolved
  -> run_done_resolved_like
  -> run_done_submitted
  -> official_resolved / official_unresolved / official_infra_failure
```

### 状态定义

1. `created`
   - task 上下文刚建立
2. `active`
   - 运行中，有 actions 持续进入
3. `run_done_unresolved`
   - 本地收尾为失败或未解决
4. `run_done_resolved_like`
   - 本地看起来成功，但还没有 official eval
5. `run_done_submitted`
   - 已提交 patch，等待 official eval
6. `official_resolved`
   - 官方评测成功
7. `official_unresolved`
   - 官方评测未解决
8. `official_infra_failure`
   - 官方评测环境问题

### 转移权限

| From | To | 触发方 |
| --- | --- | --- |
| `created` | `active` | `handle_plan_generated` / `handle_action_error` |
| `active` | `run_done_*` | `handle_run_done` |
| `run_done_*` | `official_*` | `apply_evaluation_feedback` |

---

## 7.2 `SubtaskInstance` 状态机

```text
projected_candidate
  -> locally_supported
  -> locally_failed
  -> eval_context_attached
  -> deprecated
```

### 状态说明

1. `projected_candidate`
   - 冷路径刚投影出来
2. `locally_supported`
   - 有本地事实支持其阶段性完成或推进
3. `locally_failed`
   - 本地事实支持该子任务失败或阻塞
4. `eval_context_attached`
   - 收到 official eval 上下文，但不代表它就是最终因果对象
5. `deprecated`
   - 被治理层判定为不再参与后续主视图

### 转移权限

| From | To | 触发方 |
| --- | --- | --- |
| `projected_candidate` | `locally_supported` | `handle_run_done` / projector |
| `projected_candidate` | `locally_failed` | `handle_run_done` / projector |
| `locally_*` | `eval_context_attached` | `apply_evaluation_feedback` |
| `*` | `deprecated` | `ObjectGovernancePolicy` |

### 禁止事项

1. `official_eval_feedback` 不得直接把 `projected_candidate` 标成“真实成功子任务”

---

## 7.3 `SubtaskEdge` 状态机

```text
candidate
  -> supported_candidate
  -> suppressed
  -> deprecated
```

### 状态说明

1. `candidate`
   - 刚根据投影关系生成
2. `supported_candidate`
   - 有 attempt 级证据支持其可能有效
3. `suppressed`
   - 被官方结果或治理层认为不应继续增强
4. `deprecated`
   - 进入淘汰态

### 禁止事项

1. 第一版没有“verified_causal”状态
2. 第一版不允许官方评测直接生成最终因果边

---

## 7.4 Governance 对象状态机

```text
candidate
  -> promoted
  -> suppressed
  -> deprecated
```

### 允许转移

| From | To | 触发方 |
| --- | --- | --- |
| `candidate` | `promoted` | `apply_evaluation_feedback` / governance |
| `candidate` | `suppressed` | `apply_evaluation_feedback` / governance |
| `promoted` | `deprecated` | governance |
| `suppressed` | `deprecated` | governance |

### 强制语义

1. `candidate`
   - 可被检索，但默认受预算和风险控制
2. `promoted`
   - 可进入更稳定的 curated 视图
3. `suppressed`
   - 保留可审计痕迹，但不进入默认主检索
4. `deprecated`
   - 历史保留，不再参与默认新决策

---

## 7.5 `CompilerCard` 状态机

```text
candidate
  -> injected_once
  -> promoted
  -> suppressed
  -> deprecated
```

### 状态说明

1. `candidate`
   - 新编译出的卡片
2. `injected_once`
   - 至少被实际注入过一次
3. `promoted`
   - 经治理/评测后成为较稳定卡片
4. `suppressed`
   - 被判定噪声高或价值低
5. `deprecated`
   - 退出默认视图

### 转移触发

| From | To | 触发方 |
| --- | --- | --- |
| `candidate` | `injected_once` | `on_model_query` |
| `candidate` | `promoted` | governance / eval |
| `candidate` | `suppressed` | governance / eval |
| `*` | `deprecated` | governance |

## 8. 热路径与冷路径协作协议

## 8.1 热路径

热路径包含：

1. `on_model_query`
2. `on_action_error`
3. `on_action_executed`

### 热路径只允许做

1. 轻量事实记录
2. telemetry
3. hint 注入
4. 受预算控制的去重/筛选

### 热路径禁止做

1. 重型 LLM 分析
2. embedding 生成
3. 复杂 merge / cluster
4. 完整 subtask 投影
5. 复杂治理

---

## 8.2 冷路径

冷路径包含：

1. `handle_run_done`
2. `process_attempt`
3. `SubtaskProjector`
4. `SubtaskEdgeBuilder`
5. `CardCompiler`
6. `ObjectGovernancePolicy`

### 冷路径允许做

1. 高密度摘要
2. 结构投影
3. 受时限约束的治理
4. compiler 编译

### 冷路径保底要求

超时或失败时，必须优先保住：

1. 最小 `attempt_summary_v1`
2. 最小 sidecar 记录
3. 明确 `skipped_reason`

---

## 9. 错误处理与降级语义

## 9.1 统一原则

1. 在线控制优先于长期学习
2. sidecar 失败不得阻塞主代理
3. compiler/governance 失败不得破坏已有事实层

## 9.2 推荐错误分类

| 错误类型 | 示例 | 处理方式 |
| --- | --- | --- |
| `input_validation_error` | 缺失 `instance_id` | 返回结构化错误，停止该事件处理 |
| `sidecar_write_error` | JSONL 写失败 | 记录 telemetry，继续主流程 |
| `extraction_timeout` | `process_attempt` 超时 | 保底写 fallback summary |
| `projection_error` | subtask 投影失败 | 写 `skipped_reason`，不中断 run_done |
| `compiler_error` | 编译卡片失败 | 返回空 card 集合，主流程继续 |
| `governance_error` | merge/suppress 出错 | 保留 candidate，不做 destructive change |

## 9.3 禁止事项

1. 不得因为 sidecar 失败导致 `run_done` 整体失败
2. 不得因为 compiler 失败丢失 `attempt_summary_v1`
3. 不得因为 official eval 缺字段而破坏已有对象状态

---

## 13. 实施顺序建议

### Step 1

先补 `action_success` 事件级桥接和最小 sidecar 写入。

### Step 2

在 `handle_run_done()` 中加保底成功事实补全和 sidecar 报告。

### Step 3

引入 `SubtaskProjector / SubtaskEdgeBuilder`，只产 candidate。

### Step 4

引入 `CardCompiler` 输入白名单与输出卡片白名单。

### Step 5

引入 `ObjectGovernancePolicy` 最小状态机。

### Step 6

补 official eval 到 governance/card 的受限写回。

## 14. 一句话规范结论

**v2.1 的关键不是“把更多对象定义清楚”，而是“让每个接口只做该做的事，让每次状态转移都有明确授权，让每条失败路径都能安全降级”。**
