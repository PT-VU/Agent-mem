## 0. 本次升级要兑现的两条目标

按聚焦后的口径，本次只追求这两件事在同一实例内可被稳定复现：

1. **目标 A · 概率性成功路径复用 + 探索**  
   对同一实例，已有 ≥1 次 resolved 后，后续 attempt 必须以可控概率 `p_reuse` 直接复用上次成功 patch 的关键签名（文件 + 符号 + 参数名 + 关键行），并以 `1-p_reuse` 概率在 BugInvariant 周边做有边界的探索。在 N≥5 attempt 的窗口内成功率应明显高于 NoMem 基线（目标：post-success 段 resolved 命中率 ≥ 60%）。

2. **目标 B · 已证失败 / 超时无解路径屏蔽**  
   同一实例、同一签名（文件 × 符号 × 关键失败行 / 参数名）在出现过 1 次 unresolved 或 1 次"步数耗尽未提交"之后，**后续 attempt 不得重走**。表现为：post-failure 段同签名重复提交次数 = 0，且 step-budget 耗尽时强制 fallback 到 BugInvariant 复用或 hard-submit 当前最佳候选。

## 1. 阶段9 实测暴露的闭合度缺口（升级出发点）

实测 astropy-12057（5 个 case 中唯一两组都跑满的实例）按时序：

| Attempt | 关键修复行 | resolved? | 卡片状态 |
|---|---|---|---|
| 01 | `def relabel_as(self, new_uncert_class):` | ✗ | failure_signature 仅 `evaluation_unresolved::planning::planning` |
| 02 | `def represent_as(self, other_uncert):` | ✓ | 生成 SuccessPath + BugInvariant（confidence 0.95）|
| 03 | `def represent_as(self, other_class):` | ✗ | BugInvariant 注入 162 次仍选错参数名 |
| 04 | `def represent_as(self, other_uncert):` | ✓ | 又生成一组 |
| 05 | `def represent_as(self, other_class):` | ✗ | 重蹈 03 覆辙 |
| 06 / 07 | 无 patch | incomplete | step budget L3 只是建议 |

由此识别出 5 个直接拖累目标 A/B 的闭合度缺口：

| 编号 | 缺口 | 现象 | 后果 |
|---|---|---|---|
| G1 | BugInvariantCard 是描述性摘要，非可执行模板 | hint ≤300 字符仅含 "Key change: …"，无完整 diff、无参数签名结构 | 模型读到却复制不到位（other_class vs other_uncert）|
| G2 | 失败侧无对称卡片 | unresolved 分支不抽 patch；FailureCardV2 只按 `error_type/stage/module` 粗类聚合 | 同签名失败可被无限次重复 |
| G3 | 提交动作无 patch 一致性闸门 | bridge_hook 不读 BugInvariant 去比对当前 patch | 明显违反 invariant 的 patch 也能提交 |
| G4 | 没有 reuse vs explore 显式策略层 | 仅靠"把卡片放到模型面前 + 检索加分 0.15" | Kimi 等指令跟随较弱模型实测命中 ~25% |
| G5 | local_effective 修了区分度但开环；L3 Hard Stop 仅建议 | promotion/suppression 未接入；超时不强制提交 | 失效卡持续注入；attempt 06/07 incomplete |

## 3. 模块级改动详情

### 3.1 模块 A · 把 BugInvariantCard 升级为可执行模板（对应缺口 G1）

#### 3.1.1 卡片 schema 扩展

`agent_mem/processing/evaluation_feedback.py::_write_bug_invariant_card` 写入字段从描述型扩展为机器可比对、可复用：

```python
{
  "card_type": "BugInvariantCard",
  "schema_version": "1.1",
  "minimal_patch_signature": {
    "files_touched": ["astropy/nddata/nduncertainty.py"],
    "anchors": [
      {
        "file": "astropy/nddata/nduncertainty.py",
        "symbol_kind": "method",
        "symbol_name": "represent_as",
        "parent": "NDUncertainty",
        "param_signature": ["self", "other_uncert"],
        "return_kind": "instance"
      }
    ],
    "key_added_lines": [
      "def represent_as(self, other_uncert):",
      "        return other_uncert(self.array, unit=self.unit)"
    ],
    "key_added_lines_hash": "sha1:9a…",
    "change_type": "new_method_or_class",
    "verbatim_diff": "<full unified diff，限制 ≤8KB，超出截断并保留 anchors>"
  },
  "validation_invariant": {
    "commands": ["cd /testbed && python -m pytest astropy/nddata/tests/test_nduncertainty.py -v"],
    "must_pass_test_ids": ["test_represent_as"]
  },
  "reuse_template": {
    "mode": "verbatim_first_then_anchor_align",
    "fallback_anchor": {"file": "...", "symbol_name": "represent_as"}
  },
  "confidence": 0.95,
  "support_n": <累计 same-instance resolved 数>,
  "governance_hardness": "strong"
}
```

要点：
- `verbatim_diff` 是 hint 注入时**第一优先**的展示内容（不再压成 80 字符摘要）。
- `anchors[*].param_signature` 把"参数名"变成结构化字段，供 PatchConsistencyGate 比对。
- `key_added_lines_hash` 用于跨 attempt 等价判定（goals A/B 共用）。

#### 3.1.2 抽取逻辑增强

新增静态方法（同文件）：
- `_extract_anchors(patch_text) -> list[Anchor]`：基于 unified diff hunk header 与 AST 风格扫描提取 (file, symbol_kind, symbol_name, parent, param_signature)。Python 项目优先 `ast.parse` 新增片段。
- `_normalize_diff_for_storage(patch_text) -> str`：去掉时间戳、统一行尾、≤8KB 截断。
- `_compute_signature_hash(anchors, key_added_lines) -> str`：规则化连接关键字段后 sha1，用于"同签名"判定。

#### 3.1.3 注入展示

`bridge_hook.py::_render_card_for_injection`（新增方法，被 `_select_hints_for_injection` 调用）：
- BugInvariantCard 注入文本结构：

```
[BUG_INVARIANT · STRONG]
Last resolved attempt for this instance fixed the bug as follows. PREFER VERBATIM REUSE before exploring.

File: astropy/nddata/nduncertainty.py
Symbol: NDUncertainty.represent_as
Param signature (must match): self, other_uncert
Validation: cd /testbed && python -m pytest astropy/nddata/tests/test_nduncertainty.py -v

--- VERBATIM PATCH (reuse this verbatim unless explicitly told to explore) ---
<full diff>
--- END ---
```

- 该卡注入时**豁免 token 预算**（继承阶段 9 的 semantic 桶豁免），但单卡上限提升到原来 2 倍 token，以容纳完整 diff。

### 3.3 模块 C · PatchConsistencyGate（对应缺口 G3）

新增 `bridge_hook.py::PatchConsistencyGate`：在 Agent 即将提交前对当前 patch 与 (BugInvariant ∪ BugAntiPattern) 做结构比对。

#### 3.3.1 触发点

在 `on_actions_generated` 中检测到提交意图（`_is_patch_submission(action_text)`）时，**在动作生效之前**插入：

```python
if self._is_patch_submission(step.action):
    decision = self._patch_consistency_gate.check(
        current_patch=self._collect_current_patch_view(),
        bug_invariants=self._load_active_cards("BugInvariantCard"),
        anti_patterns=self._load_active_cards("BugAntiPatternCard"),
    )
    if decision.action == "rewrite":
        self._inject_strong_hint(decision.advice)            # 注入"你的 patch 与 invariant 不一致 / 命中 anti pattern"
        self._soft_block_runtime_guard_pattern(step, "submit_violates_consistency_gate")
        return
    elif decision.action == "force_reuse":
        self._rewrite_action_to_apply_invariant_patch(step, decision.target_invariant)
    # decision.action == "allow": 直通
```

#### 3.3.2 决策规则

```python
def check(current_patch, bug_invariants, anti_patterns) -> Decision:
    sig_now = signature_of(current_patch)            # anchors + key_added_lines_hash + param_signature

    # B 优先：先看是否命中已知失败签名
    for ap in anti_patterns:
        if signature_distance(sig_now, ap.failed_patch_signature) <= 0:
            return Decision("rewrite", reason=f"matches BugAntiPattern (failed {ap.support_n}x)", target=ap)

    # A 次之：看是否对齐 BugInvariant
    if bug_invariants:
        best = max(bug_invariants, key=lambda c: c.confidence)
        d = signature_distance(sig_now, best.minimal_patch_signature)
        if d == 0:
            return Decision("allow")
        if d <= TOLERATE_DELTA and is_explore_attempt():
            return Decision("allow")                  # 探索预算允许的偏离
        # 命中关键字段差异（如参数名错）→ 强制重写或强制复用
        if param_signature_mismatch(sig_now, best):
            return Decision("rewrite", reason="param signature mismatch with BugInvariant")
    return Decision("allow")
```

签名距离最简实现：files_touched 集合差 + anchors 关键字段（symbol_name, param_signature）逐字段比对。优先按"参数名是否一致"做硬规则，因为 12057 案例核心 miss 就在参数名。

#### 3.3.3 token & 性能预算

- Gate 仅在 submission step 触发，每 attempt 触发 ≤2 次（提交+复检）
- 不调用 LLM，纯结构化 diff 解析

### 3.4 模块 D · ReuseExploreScheduler（对应缺口 G4）

#### 3.4.1 算法

attempt 启动时（`bridge_hook.__init__` 中读到 instance 历史卡片之后）做一次决策：

```python
n_resolved = count_active_cards("BugInvariantCard", instance_id)
n_failed   = count_active_cards("BugAntiPatternCard", instance_id)

if n_resolved == 0:
    self._mode = "explore_fresh"             # 无成功历史 → 完全自由
    self._p_reuse = 0.0
elif n_failed == 0 and n_resolved >= 1:
    self._mode = "reuse_dominant"
    self._p_reuse = min(0.5 + 0.2 * n_resolved, 0.9)
else:
    # 已有成功也已有失败：根据"对成功的支持度 vs 对失败的多样性"调
    self._p_reuse = clip(0.6 + 0.1*(n_resolved - n_failed), 0.4, 0.85)

draw = rng.random()
self._this_attempt_strategy = "VERBATIM_REUSE" if draw < self._p_reuse else "EXPLORE_AROUND_INVARIANT"
```

#### 3.4.2 行为差异

| 策略 | 注入头部 prompt | PatchConsistencyGate |
|---|---|---|
| `VERBATIM_REUSE` | `"This attempt is in REUSE mode. Apply the BUG_INVARIANT verbatim diff as-is. Run the validation. Submit. No new exploration."` | `param_signature_mismatch` 触发 force_reuse |
| `EXPLORE_AROUND_INVARIANT` | `"This attempt is in EXPLORE mode. The previous resolved patch is shown for reference. You may modify ONLY within the listed anchor files. AVOID all listed BUG_ANTI_PATTERN signatures."` | `signature_distance ≤ TOLERATE_DELTA` 允许；命中 anti-pattern 仍 rewrite |
| `explore_fresh` | 不注入复用 prompt | gate 仅做 anti-pattern 屏蔽（首攻击场景，本次不优化）|

#### 3.4.3 随机源与可复现

- `rng = random.Random(seed=hash((instance_id, attempt_id, run_id)))` 保证同 attempt 决策可复现
- 决策结果写入 `attempt_context.reuse_explore_decision`，便于事后分析
- 提供环境变量 override：`AGENT_MEM_FORCE_STRATEGY={reuse|explore|auto}`，便于消融实验

#### 3.4.4 与现有 step budget 的协同

当 attempt 处于 `VERBATIM_REUSE` 模式：
- L1 Guardrail 阈值从 15 步降到 8 步（更激进地催促"既然要复用就别瞎走"）
- L3 Hard Stop 触发时 → 自动改写为"立即应用 BugInvariant.verbatim_diff 并提交"（见模块 E）

### 3.5 模块 E · 闭环 local_effective + L3 强制提交（对应缺口 G5）

#### 3.5.1 反馈接回卡片置信度

新增 `bridge_hook.py::_apply_local_effective_feedback`（在 attempt 收尾时调用，最迟在 `apply_feedback` 写入前触发一次）：

```python
def _apply_local_effective_feedback(self):
    for card_id, stats in self._injected_card_stats.items():
        success = stats["success_events"]
        error   = stats["error_events"]
        local_effective = success > 0 and success >= error
        # 持久化到 graph_store：调整该卡 confidence ± 0.05，governance_hardness 降一档
        graph_store.adjust_card(card_id,
            delta_confidence = +0.05 if local_effective else -0.10,
            demote_if_below = 0.4,                # 低于阈值 → 标记 disabled
            reason="local_effective_feedback",
        )
```

`graph_store` 需配套支持：
- `adjust_card(card_id, delta_confidence, demote_if_below, reason)`：原子更新置信度与状态
- 检索阶段 `query_compiler_cards_v21` 过滤 `state == "disabled"` 的卡

#### 3.5.2 L3 Hard Stop 升级为强制提交

`bridge_hook.py::_check_step_budget_triggers` 的 L3 分支：

```python
if total >= self._step_budget_hard_stop and not self._patch_candidate_exists:
    if self._has_active_bug_invariant():
        # 有可复用的成功路径 → 强制改写动作为"应用 invariant verbatim 并提交"
        self._rewrite_action_to_apply_invariant_patch(self._latest_step, self._best_invariant())
        self._record_event("step_budget:l3_force_reuse")
    else:
        # 没有 invariant 可复用 → 强制提交当前最佳候选（哪怕没改也提交一个 noop 患/上次最近草稿）
        self._rewrite_action_to_force_submit(self._latest_step)
        self._record_event("step_budget:l3_force_submit")
```

新增方法：
- `_rewrite_action_to_apply_invariant_patch(step, card)`：把 `step.action` 替换为执行 `apply_patch <verbatim_diff>` 后跟 `submit`
- `_rewrite_action_to_force_submit(step)`：把 `step.action` 替换为 `submit`，与现有 `_soft_block_runtime_guard_pattern` 同样的硬改写路径

#### 3.5.3 incomplete 兜底

attempt_06/07 类型的 incomplete（无 patch）若发生，触发 `_record_event("incomplete:no_patch_after_l3")`，并在 unresolved 分支按"空 patch + 失败原因 = step_budget_exhaustion"写入 BugAntiPatternCard，使后续 attempt 的 ReuseExploreScheduler 直接跳到 `VERBATIM_REUSE`（前提是有 invariant 可用）。

`agent_mem/processing/failure_card_builder.py` 中 `error_signature` 现在是 `{error_type, error_stage, error_module}`。新增字段：

```python
error_signature = {
```

## 4. 数据流（resolved / unresolved 双链路）

### 4.1 resolved 后的写入链

```

 └→ EvaluationFeedbackProcessor.apply_feedback()
       ├→ _write_success_path_card()
       └→ _write_bug_invariant_card()        [模块 A 增强 schema]
            ├→ _extract_anchors()
            ├→ _compute_signature_hash()
            └→ upsert compiler_cards_v21: BugInvariantCard with verbatim_diff
```

### 4.2 unresolved 后的写入链（新增）

```
official_eval_feedback(unresolved)
 └→ EvaluationFeedbackProcessor.apply_feedback()
       ├→ failure_card_builder.write_failure_card_v2()  [增加 patch_signature_hash]
       └→ _write_bug_anti_pattern_card()                [模块 B 新增]
            ├→ _extract_anchors(failed_patch)
            ├→ _compute_signature_hash()
            └→ upsert compiler_cards_v21: BugAntiPatternCard
                  └→ if (instance, signature) 已存在 → support_n+=1, confidence↑, hardness↑
```

### 4.3 后续 attempt 的注入与门控链（增强）

```
attempt_start
 └→ ReuseExploreScheduler.decide(instance_id, history)   [模块 D]
        → mode in {VERBATIM_REUSE, EXPLORE_AROUND_INVARIANT, explore_fresh}

on_model_query
 └→ _select_hints_for_injection()
       ├→ semantic 桶：BugInvariant + BugAntiPattern + SuccessPath（含完整 diff，豁免预算）
       ├→ closure / repair / validation / generic 桶按原有顺序
       └→ _render_card_for_injection() 输出含 [BUG_INVARIANT · STRONG] / [BUG_ANTI_PATTERN] 标记

on_actions_generated
 ├→ _update_step_budget()
 ├→ _check_step_budget_triggers()
 │     └→ L3 触发 → 强制 reuse/submit            [模块 E]
 └→ 若 _is_patch_submission(action) →
       PatchConsistencyGate.check()             [模块 C]
         ├→ allow      : 放行
         ├→ rewrite    : soft block + 注入修正提示
         └→ force_reuse: 改写为 apply invariant verbatim + submit

attempt_end
 └→ _apply_local_effective_feedback()           [模块 E]
       └→ graph_store.adjust_card() 更新被注入卡的 confidence/state
```

## 6. 实施分批与风险

### 6.1 推荐分批顺序

| 批次 | 模块 | 风险 | 可独立验证 |
|---|---|---|---|
| Batch 1 | 模块 A（schema + verbatim diff 注入）| 低 | 单元测试 + 单题观察 |
| Batch 2 | 模块 B（BugAntiPatternCard）+ 失败签名细粒度化 | 中（涉及 graph_store upsert key 变更）| 单题 attempt 03/05 不再重复 |
| Batch 3 | 模块 C（PatchConsistencyGate）| 中（拦截动作可能误判）| 灰度：仅注入提示不强改写，先观察 N 个 attempt |
| Batch 4 | 模块 D（ReuseExploreScheduler）| 中（影响 attempt 行为分布）| 用 `AGENT_MEM_FORCE_STRATEGY` 做消融 |
| Batch 5 | 模块 E（local_effective 接回 + L3 强制提交）| 高（强改写动作可能伤好 attempt）| 先开 L3 dry-run，记录而不真的改写 |

### 6.2 主要风险点

1. **PatchConsistencyGate 误判** — anchors 抽取依赖 AST/diff 解析，对复杂 patch（多文件、跨语言）可能取偏。  
   缓解：第一版只对"params 不一致"和"key_added_lines_hash 完全等于 anti-pattern"做硬规则；其他差异降级为提示，不强改写。

2. **VERBATIM_REUSE 复用的 patch 可能因仓库状态漂移失败** — 如果 testbed 已存在部分修改，verbatim apply 会冲突。  
   缓解：在应用前 `git stash` 一次性清理；apply 失败 → 自动降级为 EXPLORE_AROUND_INVARIANT。

3. **BugAntiPatternCard 误屏蔽** — 同 signature 不代表"必然失败"，可能是别的运行环境因素导致。  
   缓解：support_n=1 时 governance_hardness=guardrail（仅提示），support_n≥2 才升 strong（参与 gate 强阻断）。

4. **L3 强制提交伤害正在进展的 attempt** — 50 步可能仍在合理探索。  
   缓解：仅当 `_patch_candidate_exists == False` 时强制；同时把 hard_stop 阈值提高到 60 并保留环境变量 override。

### 6.3 回滚开关

所有模块挂在环境变量后面，默认 OFF，逐批开启：
- `AGENT_MEM_BUG_INVARIANT_VERBATIM=1` / 默认 0
- `AGENT_MEM_BUG_ANTI_PATTERN=1` / 默认 0
- `AGENT_MEM_PATCH_CONSISTENCY_GATE={off|advise|enforce}` / 默认 off
- `AGENT_MEM_REUSE_EXPLORE={off|auto|reuse|explore}` / 默认 off
- `AGENT_MEM_LOCAL_EFFECTIVE_FEEDBACK=1` / 默认 0
- `AGENT_MEM_L3_FORCE_SUBMIT={off|dry_run|enforce}` / 默认 off

1. 跨题（cross-instance）AtomicBelief promotion：仍按阶段 9 决策保留到下阶段。本方案所有签名/卡片均 same-instance scope。
2. ConstraintCandidate + 完整 PolicyGate 抽象：本方案直接把 gate 写在 bridge_hook 里，最小闭环优先；后续再抽象。

4. LLM 辅助签名抽取：只做规则化抽取，避免引入推理依赖。

## 8. 一句话总结

> 阶段 9 已经实现了"记住成功"，本次升级补齐"**复用成功 · 屏蔽失败 · 闭环反馈**"的可执行闭环：把 BugInvariant 升级为 verbatim 模板、对称引入 BugAntiPattern、在提交动作上挂 patch 一致性闸门、用概率调度器在 reuse / explore 之间稳定切换、把 local_effective 反馈接回卡片置信度、把 L3 Hard Stop 从建议升为强制。

兑现这条闭环之后，目标 A（概率性复用 + 探索）与目标 B（屏蔽已证失败 / 超时无解路径）即可在同一实例的 N≥5 attempt 窗口内被稳定观测到。
