# 阶段五系统升级工程指导文件（基于阶段四实验复盘）

> 输入依据：`PDDL_work_mem/02_task_management/phase_history/阶段5/阶段四实验结果和总结分析.md`  
> 目标：把“可运行的 AgentMem”升级为“稳定、可解释、可复用、可验证增益的 AgentMem”。  
> 说明：本文仅给逐步升级指导，不做时间规划。

---

## 0. 升级总原则（执行前固定）
1. 先修链路稳定性，再扩经验数量，再提升策略复杂度。
2. 任何升级必须可观测：每条经验要能回答“从哪来、何时注入、是否有效”。
3. 任何扩容必须有质量门禁：宁可少量高质量经验，不要高噪声堆积。
4. 评测口径固定：`planned/submitted/resolved/incomplete` 四项同时看。
5. 增益验证实验不得采用截断主轨迹的配置（例如过低 `PER_INSTANCE_CALL_LIMIT`），否则结果仅能证明链路连通，不能证明学习增益。

---

## 1. 基线冻结与独立运行保障
### 目标
确保后续所有改动可回归、可对比、可断点续跑。

### 实施要点
1. 固化 with_mem/no_mem 两套独立脚本与配置，禁止互相依赖目录。
2. 固化统一输出结构：`run_outputs`、`metrics`、`eval_reports`、`memory_artifacts`。
3. 固化实验元数据：模型名、参数、数据集切片、限制条件、代码版本哈希。

### 验收标准
1. 同一命令在干净环境可直接运行。
2. 中断后可自动续跑到下一未完成实例。
3. 不再出现“路径重构导致实验失败”的文件找不到错误。

---

## 2. 事件契约与实例级可追踪性改造
### 目标
打通“事件 -> 经验 -> 注入 -> 效果”的实例级归因链路。

### 实施要点
1. 统一 HOOK payload 契约，强制包含：`instance_id`、`attempt_id`、`event_type`、`timestamp`、`source`。
2. 所有经验对象写入 `source_event_ids` 与 `source_instance_id`。
3. 注入时生成 `intervention_id`，后续 N 步动作与该 ID 绑定。

### 验收标准
1. 任意 resolved/unresolved 样本都可追溯注入来源。
2. 不再出现大面积 `instance_id=main` 的不可归因事件。

---

## 3. Tool A 稳定性与降级路径改造（P0）
### 目标
降低提取链路前端丢包，避免超时导致经验断流。

### 实施要点
1. 超时分层：快速路径超时 + 重试路径超时（双档）。
2. 加熔断与降级：连续失败后进入轻检索（缓存结果 + 低成本规则）。
3. 调整调用方式：主流程异步请求，读取最近一次成功结果，避免阻塞主决策。
4. 记录调用结果分类：成功、超时、降级命中、硬失败。
5. 保留“提取到注入”的串联状态日志：`plan_generated -> tool_a_response -> hint_buffered -> on_model_query_injected`，每一步都写可统计计数。

### 验收标准
1. Tool A timeout 比例显著下降。
2. `external_tool_response / plan_generated` 达到门槛。
3. 主流程不因 Tool A 单点失败中断。
4. 串联状态计数连续可见，不再出现“触发很多但无法解释丢失点”。

---

## 4. 经验提取覆盖率改造（P0）
### 目标
从“只会提计划经验”升级为“计划+错误+结束态”全链路提取。

### 实施要点
1. 强制启用三类提取入口：`plan_generated`、`action_error`、`run_done`。
2. unresolved 样本强制产出 `failure_card_v2`（允许低置信版本）。
3. `run_done` 失败重试后仍失败时，写本地保底提取记录，防止空产出。
4. 明确“可提取字段白名单”：工具参数、关键错误签名、补丁摘要、测试结果。
5. 修复 `run_done` 稳定性：针对 `tool_b` 超时和 `no_active_task` 提供重试与兜底回写，不允许 silently drop。
6. 明确区分两类置信度：`item_confidence`（单条经验）与 `batch_confidence`（本轮聚合），禁止混用。

### 验收标准
1. `external_tool_response / plan_generated >= 0.35`（低于阈值 hard fail）。
2. `memory_hint_buffered >= 0.15 * external_tool_response`（低于阈值 hard fail）。
3. `action_error` 覆盖率（error-like observation 命中）`>= 0.60`。
4. `failure_card_v2` 数量与 unresolved 数量接近 1:1。
5. 不再出现“运行很多、失败资产为 0”的情况。

---

## 5. 抽象经验去过度合并与上限解除改造（核心）
### 目标
解决经验稀疏与同质化，保留有区分度的可复用经验。

### 实施要点
1. 升级 fingerprint 维度：加入 `error_signature`、`tool_sequence`、`changed_file_pattern`、`test_signal`。
2. 取消“单任务抽象经验条数上限”，改为“质量阈值 + 去重阈值”。
3. 同一任务内允许多条抽象经验并存，按场景标签分桶。
4. 抽象经验写入支持证据计数与反例计数，避免盲目强化。
5. 增加“模板污染抑制器”：对高频模板（如泛化计划语句、run_done 空泛摘要）设置重复写入惩罚。

### 验收标准
1. `abstract_experience` 数量不再异常收敛到 1~2 条。
2. 同一实例多次 attempt 能观察到经验多样性增长。
3. 抽象经验文本重复率下降。
4. 同一实例 attempt2~5 的注入内容相似度明显下降（不再长期固定同三条）。

---

## 6. 检索层改造：分型检索与返回上限解除
### 目标
让检索结果与当前问题类型匹配，减少“只返回 planning 模板”。

### 实施要点
1. query_type 扩展并强制分类：`planning`、`error_recovery`、`test_failure_fix`、`regression_guard`。
2. 取消固定 top-k 小上限，改为“动态预算 + 最低质量阈值”。
3. 对 failure_card、abstract、belief 分别配置召回配额，避免单类挤占。
4. 返回结果附带理由：匹配字段、相似度、历史收益、置信度。
5. 记录检索-注入损耗：候选数、过滤数、最终注入数，支持链路瓶颈定位。

### 验收标准
1. query_type 分布不再极端偏向 planning。
2. 每次注入前可看到多类型候选而非单一模板。
3. planning 不再长期独占，`error_recovery/test_failure_fix/regression_guard` 在失败实例中稳定出现。

---

## 7. 注入策略改造：去固定上限 + 必要性判定 + 注入后验证
### 目标
让注入从“固定条数提示”变为“按价值预算的干预”。

### 实施要点
1. 去掉固定 `max_hints` 上限，改为 token/上下文预算控制。
2. 注入前做必要性判定：无增益时不注入，避免噪声。
3. 注入后记录 N 步内行为变化：是否执行建议动作、是否减少重复错误、是否推进测试。
4. 对低价值反复注入条目做衰减或隔离。
5. 显式保留注入触发命中率：触发事件数、进入 buffer 数、真正注入数、注入后生效数。

### 验收标准
1. 注入覆盖率提升，且注入内容差异性提升。
2. 注入后行为改进信号可统计（不是只记录“注入发生过”）。
3. 注入触发命中率可解释，能定位“触发多但注入少”的具体损耗点。

---

## 8. 经验存储结构升级（Memory Schema V2）
### 目标
把“可写文件”升级为“可管理的经验资产库”。

### 实施要点
1. 统一经验对象结构：
   - `experience_id`
   - `type`（failure/abstract/belief/repair_pattern）
   - `source`（instance/attempt/event）
   - `content`
   - `quality`（confidence/uplift/last_used）
   - `links`（related_experience_ids）
2. 建立经验关系：失败卡 -> 抽象经验 -> 注入记录 -> 结果反馈。
3. 增加经验生命周期：新建、验证中、稳定、降级、归档。
4. 归档强制保留“逐 attempt 读写映射”：每次读取哪些经验 ID、写入哪些经验 ID、版本号与来源事件。

### 验收标准
1. 任意经验都可追踪来源和效果。
2. 能按质量与时效筛选经验，不再全量混用。

---

## 9. 回流学习与质量门控改造
### 目标
建立“用了经验之后是否真的有用”的自动回流机制。

### 实施要点
1. 注入后自动计算局部 uplift：步数变化、错误重复率变化、测试推进变化。
2. 对负向经验自动降权，对长期无效经验淘汰。
3. unresolved 样本进入 RCA 管道，输出可执行 repair pattern。
4. 设立硬门禁：未达到覆盖率/质量阈值时，禁止扩大样本规模。
5. RCA 输出必须绑定回经验对象：`failure_card -> rca_hypothesis -> repair_pattern -> intervention`，缺一不可。

### 验收标准
1. 经验库质量分布可见，低质经验占比下降。
2. 跨实例复用命中率与有效率可稳定统计。
3. unresolved 样本可见 RCA 产物，不再出现“RCA参与但无落地对象”的情况。

---

## 10. 实验与评测闭环改造（官方口径）
### 目标
保证“过程指标改善”能转化为“官方 solved_rate 可验证提升”。

### 实施要点
1. 每轮实验强制输出：
   - 过程指标（提取/注入/质量/失败类型）
   - 结果指标（planned/submitted/resolved/incomplete）
   - 实例级差异（only_with / only_no）
2. 每轮结束自动触发官方评测流水线。
3. 评测报告附带失败归因：工具失败、提取缺失、注入无效、运行中断。
4. 每轮实验归档强制包含：
   - 事件日志（含 `memory_hint_buffered/memory_injected`）
   - 持久化快照（`observation_kg/belief_graph/abstract_experiences/failure_cards_v2`）
   - 逐 attempt 读写映射（读了哪些 ID、写了哪些 ID）
5. 每轮报告必须区分三层结论：链路触发（connectivity）、经验增量（memory quality growth）、任务结果（task outcome）。

### 验收标准
1. with_mem 相对 no_mem 在 planned solved_rate 上可重复提升。
2. `incomplete_instances` 不高于 no_mem 对照组 `+2`。
3. 注入覆盖率至少达到 `30/50`（Full first50 口径）。
4. 注入组 solved_rate 不低于非注入组 solved_rate。
5. 提升可以由“具体经验条目 -> 具体行为变化 -> 具体实例结果”解释。

---

## 11. 执行顺序（无时间版）
1. 先做第 2、3、4 步，修可追踪与稳定性。
2. 再做第 5、6、7 步，修经验数量与注入有效性。
3. 再做第 8、9 步，修资产化与回流学习。
4. 最后做第 10 步，固定评测闭环与结果验收。

---

## 12. 升级完成判定（DoD）
1. 经验提取不再稀疏：三入口覆盖达标，失败资产稳定产出。
2. 经验注入不再模板化：多类型、可执行、可验证、可回流。
3. with_mem 在官方评测中相对 no_mem 有稳定净增益，且 incomplete 不失控。
4. 任意一个成功/失败实例都能完整回答：
   - 提取了什么经验？
   - 何时注入了哪些经验？
   - 注入后行为是否改变？
   - 结果是否因此受益？

---

## 13. 对照矩阵：阶段四总结分析 -> 阶段五工程落地点
1. 提取覆盖偏低（14.8%） -> 第 3、4、10 节（稳定性+三入口+硬阈值+评测门禁）。
2. `action_error` 基本失效 -> 第 4 节（强制入口+覆盖率门槛）。
3. Tool A 高频超时 -> 第 3 节（双档超时+熔断降级+异步解耦）。
4. 注入覆盖仅 16/50 -> 第 7、10 节（触发命中率度量+30/50门槛）。
5. 触发多、注入少 -> 第 3、6、7 节（串联状态计数+损耗跟踪）。
6. 注入内容模板化 -> 第 5、6、7 节（去过度合并+分型检索+质量门控）。
7. 存储规模与运行规模不匹配 -> 第 4、5、8、9 节（失败资产硬产出+schema v2+回流）。
8. `failure_cards_v2=0` / `repair_patterns_v2=0` -> 第 4、9 节（unresolved强制产出+RCA绑定落地）。
9. query_type 单一（planning偏置） -> 第 6 节（四类分型+配额召回）。
10. `instance_id=main` 归因失败 -> 第 2 节（payload契约+intervention_id）。
11. 可解释干预闭环缺失 -> 第 2、7、10 节（N步验证+实例级归因+三层报告）。
12. incomplete 上升风险 -> 第 10 节（`incomplete<=对照+2` 强门禁）。
13. 指标表象与效用偏差 -> 第 10 节（三层结论+官方口径联动）。
14. 经验质量去重降噪不足 -> 第 5、6、9 节（模板惩罚+阈值+rerank+降权淘汰）。
15. smoke 轨迹截断导致无学习增益 -> 第 0、10 节（禁用截断型增益验证配置）。
16. run_done 可观测性偏差（tool_b timeout/no_active_task） -> 第 4 节（重试+兜底回写）。
17. 逐 attempt 经验读写不可追踪 -> 第 8、10 节（读写映射强制归档）。
18. 质量门控混用（整体/条目置信度） -> 第 4 节（`item_confidence` 与 `batch_confidence` 分离）。
